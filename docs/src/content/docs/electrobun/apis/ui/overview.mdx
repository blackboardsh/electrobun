```ts
import { live, signal, ui, createUIWindow } from "electrobun/main/ui";
```

Warren has two renderers over one core: this page covers the **GPU
renderer** (main process, Dawn); the same reactivity, JSX, and control flow
also render into real DOM inside webviews via
[`electrobun/browser/ui`](/electrobun/apis/ui/browser-dom/). Store and
model code written against the primitives runs unchanged on both sides.

## How rendering works

Your components build a **retained tree** of nodes (boxes, text, native-layer
anchors). Reactive props are fine-grained: each thunk prop becomes one effect
that writes one tree property. A frame tick polls input and — only when
something marked the tree dirty — runs layout, flattens the tree into an
instance buffer, and draws it to the window's Dawn surface. The default text
backend shares the quad pipeline; custom text draws are interleaved in tree
order. Idle UI does no layout, paint, or GPU work; hidden windows skip the tick
entirely.

UIWindows are regular [`GpuWindow`](/electrobun/apis/webgpu/)s underneath —
same native window, same full-window `WGPUView`, same surface. The UI runtime
is a layer on top, not a different GPU stack.

## Custom text rendering

Both `createUIWindow` and `createUIView` accept `createTextRenderer`, a
per-mount factory that receives Warren's borrowed `device` and target `format`.
It may return a `UiTextRenderer` asynchronously, allowing fonts and pipelines
to load before the UI mounts. Omitting it keeps the built-in text backend.
Existing JSX and `ui.text()` calls use the supplied backend automatically.

The renderer implements four methods:

| Method | Contract |
| --- | --- |
| `measure(text, size)` | Return `{ w, h }` in logical points for layout. Keep this synchronous. |
| `prepare(runs, viewport)` | Prepare the visible text runs before the pass begins; upload resources and retire absent node IDs here. The viewport contains logical `width`/`height` and actual `pixelWidth`/`pixelHeight`. |
| `draw(pass, run)` | Draw one run into the borrowed pass. Runs carry node `id`, `text`, `size`, packed `0xRRGGBBAA` `color`, and logical `x`/`y`. Warren sets viewport and ancestor clipping before the call and preserves tree paint order. |
| `dispose()` | Release resources owned by the backend. Warren calls this before destroying its device, including when mount initialization fails. |

Import `UiTextRendererFactory`, `UiTextRenderer`, `UiTextRun`, and
`UiTextViewport` as types from `electrobun/main/ui`. The backend must set its
own drawing pipeline and bindings. Do not retain or end the pass, submit it,
or destroy the borrowed device. Warren restores its quad state after text.
A failed draw ends and discards that frame rather than presenting it.

The `device` and `pass` are Electrobun's native adapter classes. They implement
part of WebGPU and are not assignable to the complete `@webgpu/types`
interfaces. A library such as TypeGPU needs an application-owned compatibility
adapter at this boundary, covering the native methods that library exercises.
This hook does not add missing WebGPU features or a text-library dependency.

## createUIWindow

```ts docs=syntax
const uiWindow = await createUIWindow(options, app);
```

Creates a `GpuWindow`, mounts the tree, and starts the frame tick. The `app`
callback builds the UI with the [element API](/electrobun/apis/ui/components/).

| Option | Type | Default | Purpose |
| --- | --- | --- | --- |
| `title` | `string` | — | Window title. |
| `width`, `height` | `number` | — | Initial content size. |
| `titleBarStyle` | `"hidden" \| "hiddenInset" \| "default"` | `"hiddenInset"` | `hiddenInset` keeps the window frame equal to the content area. |
| `transparent` | `boolean` | `false` | Alpha-composited window. Pair with an alpha `background` and a rounded root box for floating panels. |
| `alwaysOnTop` | `boolean` | `false` | Keep the window above normal windows. |
| `background` | `string` | `"#141420"` | Clear color behind the tree. Accepts `#rgb`, `#rrggbb`, `#rrggbbaa`. |
| `createTextRenderer` | `UiTextRendererFactory` | Built-in text | Supply per-mount text measurement and GPU drawing. |
| `tickMs` | `number` | `8` | Frame tick interval. Input polls every tick; rendering only on dirty ticks. |

Returns `{ window, context, dispose }`:

- `window` — the underlying `GpuWindow` (`show()`, `hide()`, `isVisible()`,
  `setPosition()`, `setSize()`, `setAlwaysOnTop()`, ...). Hiding the window
  suspends all UI work until it is shown again.
- `context` — the mount's `UiContext` (tree, reactive `focusedId` /
  `hoveredId`, handler registries). Mostly useful for advanced integrations
  and tests.
- `dispose()` — tears down the reactive scope and closes the window.

## createUIView

```ts docs=syntax
const uiView = await createUIView(view, options, app);
```

Mounts a tree into an existing [`WGPUView`](/electrobun/apis/webgpu/) instead
of a whole window — the mechanism behind
[`<electrobun-ui>`](/electrobun/apis/ui/ui-tag/) overlays. `options` accepts
`background`, `tickMs`, and `createTextRenderer`. The view's frame supplies size and pointer offset.

## registerUIRoot

```ts docs=syntax
const registration = registerUIRoot("overlay-name", { background: "#1b1b28" }, app);
```

Mounts `app` into every
[`<electrobun-ui name="overlay-name">`](/electrobun/apis/ui/ui-tag/) tag that
appears in your webviews. Each tag instance gets its own tree. Views removed
by the page are detected and disposed. Call `registration.dispose()` to stop.

## Input model

- **Pointer** — native view events on macOS (move, press, release, wheel,
  enter/exit), with a polling fallback elsewhere: hover enter/leave, press,
  release, click. Mouse wheel scrolls the innermost `overflow: "scroll"`
  container. A press outside any hittable node blurs focus. Nodes opt in
  via handlers (`onClick`, `onPointerDown`, `onPointerUp`,
  `onPointerEnter`, `onPointerLeave`).
- **Keyboard** — native key events route to the focused node's `onKeyDown`
  first (bubbling through ancestors; return `true` to stop), then to
  window-level handlers registered with `onKey(handler)`. On macOS, events
  carry the keyboard layout's characters (`e.chars`).
- **Focus** — `focusable: true` nodes take focus on click; `textInput`
  autofocuses when asked. `ctx.focusedId()` is reactive.
- **Window dragging** — `windowDrag: true` nodes move the window when
  dragged; a press without movement still delivers `onClick`.

## Coordinates and units

All sizes and positions are logical points with the origin at the window
content's top-left. Colors are hex strings (or `0xRRGGBBAA` numbers).

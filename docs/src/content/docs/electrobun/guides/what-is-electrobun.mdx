title: "What is Electrobun?"
description: "A compact cross-platform desktop framework built around native views and a small runtime."
---

Electrobun is a desktop application framework for macOS, Windows, and Linux. It
combines web-based user interfaces with native windows, menus, trays, updates,
WebGPU surfaces, and platform integration.

## The 2.x stack

Electrobun 2.x separates development tooling from application runtime:

- **Hutch** installs dependencies, runs scripts, bundles code, acquires pinned
  toolchains, and creates signed distribution artifacts.
- **Cottontail** is the default JavaScript and TypeScript main-process runtime.
  It provides Node.js and Bun-compatible APIs on JavaScriptCore.
- **Electrobun Core** implements cross-platform windows, views, RPC, menus,
  trays, updates, and native integration.
- **System webviews** render UI by default: WKWebView on macOS, WebView2 on
  Windows, and WebKitGTK on Linux.
- **CEF** is an optional pinned Chromium renderer for applications that prefer
  browser consistency over bundle size.

Applications may replace Cottontail with Bun, Zig, Rust, Go, or Odin as their
main process while using the same Hutch build and packaging workflow.

## Why Electrobun

- Use TypeScript and existing web frameworks for application UI.
- Keep privileged native APIs out of page JavaScript and communicate through
  typed RPC.
- Use native windows and platform APIs without shipping Chromium by default.
- Embed independent `<electrobun-webview>` and `<electrobun-wgpu>` surfaces in
  an application's HTML layout.
- Produce self-extracting Zstandard-compressed installers.
- Generate binary-diff updates with a full-download fallback.
- Build production and canary channels independently.

## Process model

The main process owns application state and native objects. Each browser view is
isolated from it and communicates through Electrobun's RPC and event bridges.
This gives an application the convenience of web UI without placing privileged
main-process APIs directly in page JavaScript.

## Distribution model

Hutch creates a runnable inner application, an outer self-extracting wrapper,
update metadata, a compressed full-update archive, and platform installer
artifacts. Code signing and notarization are integrated into the release build.
Artifacts can be hosted on static storage such as R2, S3, or GitHub Releases.

## Start building

Install Hutch and choose a template:

```bash
curl -fsSL https://hutch.blackboard.sh/hutch/install.sh | sh
hutch electrobun init
```

If Hutch is not installed yet, the npm package provides equivalent bootstrap
entry points. They install the matching Hutch channel and open the same
template and project-name prompts:

```bash
npx electrobun init
# or
bunx electrobun init
```

Continue with the [Quick Start](/electrobun/guides/quick-start/) or build the
minimal app in [Hello World](/electrobun/guides/hello-world/).

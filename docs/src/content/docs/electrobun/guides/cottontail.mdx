Cottontail is Electrobun's default JavaScript and TypeScript main-process
runtime. It is built with Zig and JavaScriptCore and provides the Node.js and
Bun-compatible APIs needed by Electrobun applications.

Hutch resolves a pinned Cottontail release while building and places that
runtime in the application bundle. End users do not install Cottontail
separately.

## Select Cottontail

New projects use Cottontail by default. The explicit configuration is:

```ts
import type { ElectrobunConfig } from "electrobun";

export default {
  app: {
    name: "Cottontail App",
    identifier: "dev.example.cottontail-app",
    version: "0.1.0",
  },
  build: {
    mainProcess: "cottontail",
    cottontail: {
      entrypoint: "src/bun/index.ts",
    },
  },
} satisfies ElectrobunConfig;
```

The `src/bun` directory and `electrobun/main` import path are retained as
compatibility names. They do not mean the application is running the Bun
binary:

```ts
import { BrowserWindow } from "electrobun/main";

new BrowserWindow({
  title: "My App",
  url: "views://mainview/index.html",
});
```

## Runtime and build ownership

| Concern | Owner |
| --- | --- |
| Execute the bundled TypeScript main process | Cottontail |
| Node.js and Bun-compatible runtime APIs | Cottontail |
| Install packages and maintain the lockfile | Hutch |
| Execute package binaries with `hutch x` | Hutch |
| Bundle main-process and webview source | Hutch |
| Acquire compilers and native platform artifacts | Hutch |
| Sign, notarize, wrap, and package releases | Hutch |

This separation keeps package management and distribution machinery out of the
runtime shipped to every application.

## Runtime compatibility

Cottontail is intended to run existing Node.js and Bun-oriented application
code, but compatibility does not make the two runtimes interchangeable in every
case. Native addons, runtime-specific implementation details, and uncommon APIs
can expose differences. Keep `bun.lock` committed and exercise your application
on every target platform before release.

<Aside type="tip">
Use the Bun main-process option when an application intentionally depends on the
actual Bun runtime. Hutch remains the build tool in that configuration.
</Aside>

## Pin Cottontail

Pin only when reproducibility requires it:

```ts
// @dash cottontail=0.2.3
```

Without a pin, production Hutch selects production Cottontail and
`hutch-canary` selects canary Cottontail. Inspect the active version with
`hutch cottontail version`.

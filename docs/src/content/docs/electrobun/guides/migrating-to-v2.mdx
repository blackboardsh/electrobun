---
title: "Migrate to Electrobun 2.x"
description: "A concise checklist for moving an existing project to Hutch and Cottontail."
---

Electrobun 2.x moves build orchestration to Hutch and makes Cottontail the
default JavaScript main process. Application code and RPC schemas usually need
little or no change; the important migration is the project boundary.

## 1. Install Hutch

```bash
curl -fsSL https://hutch.blackboard.sh/hutch/install.sh | sh
```

On Windows PowerShell:

```powershell
& ([scriptblock]::Create((irm https://hutch.blackboard.sh/hutch/install.ps1)))
```

## 2. Move product and task selection to Hutch

Remove `electrobun` from application dependencies. The npm package is now an
optional thin Hutch bootstrap and never contains the runtime or SDK.

Create `hutch.config.ts` with the exact product pin, external package manager,
and project tasks:

```ts docs=syntax
export default {
  electrobun: {
    version: "2.0.0",
  },
  packageManager: "npm",
  scripts: {
    install: ["hutch", "pm", "ci"],
    dev: ["hutch", "electrobun", "dev", "--watch"],
    build: ["hutch", "electrobun", "build", "--env=production"],
  },
};
```

Keep application and distribution settings in `electrobun.config.ts`:

```ts
import type { ElectrobunConfig } from "electrobun";

export default {
  app: {
    name: "My App",
    identifier: "dev.example.my-app",
    version: "2.0.0",
  },
  build: {
    mainProcess: "cottontail",
    cottontail: {
      entrypoint: "src/bun/index.ts",
    },
  },
} satisfies ElectrobunConfig;
```

See [Project Ownership and the Devkit](/electrobun/guides/project-ownership/)
for the full responsibility table.

## 3. Use the runtime-neutral SDK import

Main-process code should import from `electrobun/main`:

```ts
import { BrowserWindow } from "electrobun/main";

const win = new BrowserWindow({
  title: "My app",
  url: "views://mainview/index.html",
});

void win;
```

The directory may remain `src/bun`; its name does not select the runtime.
Cottontail is the default architectural path. `build.mainProcess: "bun"`
remains a first-class option, and `packageManager: "bun"` independently keeps
Bun as the external dependency manager.

## 4. Sync and verify

```bash
hutch electrobun sync
hutch run install
hutch electrobun dev
hutch electrobun build --env=canary
```

Sync verifies the selected per-platform core archive from the Electrobun GitHub
Release, caches it globally, and copies its SDKs into the generated project
`.hutch/devkit` sysroot. Templates ignore `.hutch/` by default. Hutch owns this
projection and can replace it when the selected product, target, or release
manifest changes; direct edits are not a supported customization mechanism.

Hutch builds for the current host. Verify startup, RPC, webviews, signing, and
updates on native runners for every platform you distribute.
